# ADR-0006：证据驱动的原生 Wiki 与轻量页面检索

状态：Accepted；规格版本：0.2；日期：2026-10-16。依据：用户明确授权按已讨论方案开始实施；功能完成状态仍以 SDD status 为准。

关联：[ADR-0004](0004-knowledge-source-snapshots.md)、[ADR-0005](0005-local-hybrid-retrieval.md)、[Wiki SDD](../../sdd/features/knowledge-wiki/README.md)。本记录为实施基线，不代表功能已经完成或验证。

## 背景与问题

WorkExpert 已建设版本化原文证据、结构化分块和本地混合检索。用户需要进一步把分散资料整理成可以浏览、互链、追溯和持续维护的主题知识，而不是增加另一套项目编排或知识平台。此前 KE-07 的“本体指导 Wiki”过度绑定本体前置能力，现按用户讨论调整为证据驱动、本体可选。

必须区分三个关系：Wiki 章节属于页面；Wiki 章节引用原文证据；Wiki 页面链接另一页面。页面链接不是实体关系知识图谱。模型生成的 Wiki 也不是独立于原文的新证据。

## 决策提案

1. 原生 Wiki 为知识库内的可选视图，保留“原始资料 / Wiki”入口；不另建网站、登录或编排系统。首期仅支持本地、可授权且具有完整版本证据的来源。
2. 文档结构统筹主题，原文分块提供证据；记录输入清单和覆盖率，逐块提取后按主题合并。短文可全文处理，长文不依赖一次装入上下文，也不以 TopK 检索代替完整覆盖。
3. 页面、不可变修订、章节定位、证据引用、链接、任务检查点保存在各知识库现有 evidence SQLite 的新增命名空间表中。复用同一事务边界处理发布、FTS 和原文有效头变更；不放进旧本体 sql.js，不改变 LanceDB 表。
4. 首期为页面级 FTS5/BM25 + 标题/别名精确命中；external-content 复用可重建文本投影。正文和修订才是权威内容，倒排索引可重建。不引入 Wiki Embedding、RRF、Rerank、Neo4j 或 ES 服务。现有原文混合检索不变。
5. 页面链接使用稳定 pageId，不用可改名的标题作为主键。按需进行一次邻接查询，结果有权限和预算限制；不把所有邻居默认加入检索结果或模型上下文。
6. 生成输出必须进入草稿并经有权限的用户发布；复用现有治理身份、审计与服务端编排原则，不直接耦合本体候选表。人工正文不被后台生成静默覆盖；新草稿与旧已发布修订可并存。
7. 原文更新标记过期；删除/抑制或权限收紧阻断派生正文泄露。读取时复核依赖，不只信任缓存标记。发布以输入版本及页面基线 CAS 校验，过期生成结果不得直接晋升。
8. 本体、Wiki 章节向量化、与原文的统一 RRF、MediaWiki 只读连接器均为后续独立阶段。预留来源身份，不实现外部连接、双向同步或后台自动模型调用。

## 备选方案

| 方案 | 优势 | 不采用为首期的原因 |
| --- | --- | --- |
| 本体/Neo4j 优先 | 强类型关系和关系检索 | 增加建模与运维前置要求，页面互链并不需要它 |
| Wiki 全量向量化后统一召回 | 同义表达更好 | 增加模型成本与跨库一致性，首期词法浏览闭环足够 |
| 独立 wiki.sqlite | 模块物理隔离更强 | 原文可见性与发布难以同事务，需要额外 outbox/协调 |
| 直接用 MediaWiki | 成熟协作编辑生态 | 增加服务、权限和双系统治理；未来可通过连接器接入 |
| Wiki 仅存 Markdown 文件 | 易导出阅读 | 发布指针、修订、证据和全文索引一致性维护更复杂 |
| 页面生成后自动发布 | 交互少 | 无法控制幻觉、错误合并及人工修改覆盖 |

## 代价、风险与控制

增加页面修订及 FTS 投影磁盘占用，SQLite 写入需保持短事务，模型调用绝不占写锁。共享 evidence 文件增加迁移耦合，因此采取增量 schema、备份、未来版本拒读和兼容读写器。长任务由 orchestrator 组织，storage 持久化 Wiki 域检查点，避免 API 内存任务成为唯一事实源。

轻量中文词法沿用现有 tokenizer，不承诺同义词或专业分词质量；用固定题集和真实业务评审决定是否引入后续增强。引用身份和摘要匹配只能证明来源完整，不能证明模型陈述必然成立，发布仍需核对语义。

## 迁移与回滚

首期提出 evidence v4→v5 增量迁移；具体迁移归 WK-T02，开始实现时若版本已被其他功能占用，先修订规格，禁止复用版本号。备份包含 SQLite 一致快照及原文对象引用；不手工复制活跃 WAL 主文件。无历史 Wiki 回填，不自动生成或调用模型。

实施细化：普通证据仓储继续创建 v4，并兼容读取 v5；仅显式打开 Wiki 仓储时事务迁移到 v5，避免未使用 Wiki 的用户被动升级。Wiki 仓储与证据仓储共享连接/事务边界，接口必须显式传入宿主验证过的主体与来源授权检查器；未传检查器不能读取派生内容。

回退优先关闭 Wiki 功能、保留数据、使用兼容新 schema 的读写器。旧 v4 二进制可能拒绝整个知识库，不视作安全回滚。灾难恢复须停写并恢复经过验证的一致备份，明确备份后的数据损失范围，不自动删除或降级数据库。

## 接受与验证条件

需求、契约、状态机、任务和负向测试以 SDD 为准。评审重点：权限继承的保守策略、人工发布、共享事务边界、过期内容处理、模型预算和分期边界。WK-T01 评审通过后方进入功能实现；发布前必须完成用户手册源文件及应用内产物同步。文档构建不代替设计评审和功能验收。
