# ADR-0004：知识原文、证据与检索副本分离

状态：Accepted；日期：2026-10-16。依据：用户确认双存储及复用资产文件能力，并授权分步落地。

## 决策

原始字节保存为不可变文件对象；SQLite 保存权威版本、证据和未来 Wiki；LanceDB 保存可重建检索副本，允许冗余分块正文。原文对象、资产卡片、知识文档版本是不同身份。

资产现有原地更新与物理删除语义不满足历史证据要求。因此第一阶段保留旧资产行为，从资产导入时复制独立快照，不硬链接旧资产文件。文件对象由共享 storage 模块管理，API 写入；按组织与用户分区，不跨主体去重。未来资产迁移到同一对象服务后再通过引用共享物理文件。

原文归档不等于解析/索引完成。归档失败阻止新的本地入库，解析失败保留已归档原文并返回快照引用；原文读取需要原归档主体授权，不因知识库共享自动公开。当前仅支持自有资产导入。

## 替代方案与后果

- 仅引用旧 assetId：拒绝，旧资产覆盖/删除会破坏引用。
- 只在 LanceDB 保存权威证据：拒绝，治理与索引生命周期耦合。
- 立即重构全部资产：暂不采用，避免牵连交付物、预览与项目物化。

代价为正文冗余、跨文件/SQLite/LanceDB 的一致性管理，以及迁移期间源资产与快照各存一份。采用先完成文件再提交引用，允许失败留下未引用文件，不自动清理。后续须实现安全 GC、显式彻底删除、快照管理界面、证据批次发布与检索版本过滤。

实现及测试范围见 [知识证据 SDD](../../sdd/features/knowledge-evidence/README.md)。本 ADR 描述目标边界，不代表 Wiki 或全量证据双写已经实现。
