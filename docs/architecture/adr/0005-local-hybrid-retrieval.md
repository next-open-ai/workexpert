# ADR-0005：SQLite 全文检索与本地混合召回

状态：Accepted；日期：2026-10-16。依据：用户授权实现关键词入库、BM25 召回与混合检索下一阶段。

## 决策

在各知识库现有 evidence SQLite 内使用运行时内建 FTS5，向量继续由 LanceDB 提供；不新增 ES、搜索服务或向量表结构。有效头切换、全文投影替换、删除在 SQLite 同事务内完成。原文与不可变批次不删除；全文投影可重建，不是真相源。

全文采用 external-content 表、同步触发器和显式 BM25 排序。search_chunks 保存有效片段的正文/标题及预处理 token，是可重建冗余投影，有额外磁盘成本；external-content 避免 FTS 内部再次存储 token 正文。预处理为 NFKC、小写、英文数字词、汉字单字与双字，不引入平台专用分词扩展。中文多字查询用双字，单字查询用单字；尚不声称达到词典分词、繁简转换或语义分词效果。

两路召回以等权 RRF 融合，避免直接相加 BM25 与向量分数。沿用原搜索入口，向量失败但关键词有结果时标明降级；证据/全文数据库异常不可绕过。历史无版本数据补索引后仍为 legacy-unverified。

## 备选与后果

- LanceDB FTS：本期不选，优先将全文可见性与证据头/删除同事务，减少跨存储的发布状态。
- ES/OpenSearch：本期不选，桌面本地优先不增加独立服务运维。
- 手写 BM25 遍历正文：不选，使用现成倒排索引和数据库排序。

代价：schema v3 不能直接用 v2 读取代码回滚；首次迁移与旧库补齐需要额外时间/磁盘，大库尚未做性能基准。只允许回滚到保留 v3 读取与删除过滤的代码，不删除数据库。全量代码与验收边界见 [KE-T04a](../../sdd/features/knowledge-evidence/README.md)。
