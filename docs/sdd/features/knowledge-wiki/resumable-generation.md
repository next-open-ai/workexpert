状态：已验证（工程回归）；版本：1；日期：2026-10-21。需求 WK-R18，测试 WK-R18-T；实际证据与限制见 [status](status.md)。

## 范围与交互

优先完成生成恢复；增量合并、来源联动、检索诊断与阅读维护后续分别实施。统一 Reranker、召回质量评测不实施。

新任务持久化已校验批次与归并结果；停止后提供“继续生成”，确认后只调用未完成批次。已保存页通过原幂等键重放，不覆盖人工编辑；链接仍用 CAS。当前模型标识和来源快照必须匹配，否则拒绝续跑并引导重新生成。旧任务没有检查点，仅可重新生成。不自动计费、不自动重启任务；供应商已执行但未保存返回值的调用可能再次收费。

## 契约、存储与编排

start 请求增加可选 resumeJobId；idempotencyKey 对应本次显式恢复，恢复保持原 jobId。最多20次显式恢复，重复 key 只读不再调用；同库锁与调度容量约束保持。恢复已完成任务只返回结果。输入快照及批次方案/recipe 散列与原检查点相同，原 requestHash 核对模型 provider/baseUrl/chatModel 和资料集合；不保存密钥。

任务列表优先活动任务，其余按更新时间倒序，避免续跑旧任务后刷新界面看不到它。达到20次后不再展示继续入口；旧重新生成入口保留。

SQLite v6 现有任务 payload 增加私有 `_checkpoint`（自身 schemaVersion=1），同一行原子写入进度与候选。公开 job DTO 新增 resumable 布尔值与 attemptStartedAt（每次启动时间，避免把中断期间误显示为本次等待）；list/read SQL 去掉私有字段，不将候选正文送到客户端。checkpoint 只经作用域限定的内部方法读取，最多8批、64页，序列化上限16×1024×1024个UTF-16单元。所有批次完成后保存稳定归并产物，再保存页面；恢复不重新生成 pageId。完成后清除候选以控制磁盘占用，保留恢复幂等键。来源变化在恢复前、每批调用前及保存时复查。

无表迁移，旧记录可读；旧 strict reader 不能读取新私有字段，回滚必须保留新 storage/contracts 兼容层，禁止降级数据库或覆盖真实库。关闭续跑入口不影响已保存 Wiki。
