## 数据迁移与回滚操作要求

WK-T02 只对临时 fixture 验证迁移，禁止以开发验收之名打开/迁移用户库。v4→v5 添加 Wiki 表，保留全部旧表/批次/父块，运行前检查 application_id/schema，未知未来版本拒读。单事务失败退回 v4；成功后需兼容 v5 的代码回滚，不能用旧版直接读取。

实际部署迁移前：暂停写入 → SQLite 在线备份或停库一致备份（含 WAL 正确处理）→ 验证备份可打开/计数与哈希 → 执行迁移 → 校验旧原文搜索和新 Wiki；失败不自动删除库。FTS 重建在事务中替换投影，只读取已发布且有效页面，失败回滚旧投影或返回 INDEX_UNAVAILABLE，禁止部分索引冒充完整结果。

功能关闭应停止新任务和隐藏入口，保留页面/修订/索引；关闭不表示撤销已发送供应商的请求。物理删除、GC、用户数据备份恢复需独立明确授权。

## 观测与容量

记录 requestId/jobId、阶段耗时、块覆盖率、草稿数、引用校验失败、CAS 冲突、FTS 错误、模型调用/估算用量；不落密钥、完整 prompt 或个人原文。服务端配置与日志区分用户操作取消、预算耗尽、模型错误和存储错误。

初始性能验收目标（待实测，不是已达承诺）：固定机器 10,000 页面/约 100 MiB 正文，预热后连续 100 次固定词法查询，单库 Top20 的 p95 ≤500ms、一跳 Top10 p95 ≤200ms（不含 UI/模型）；记录硬件、索引大小、冷启动、重建耗时及写入并发影响。超标先分析 SQL/索引/分页，不直接引入新服务。生成质量以脱敏业务题集评审，真实模型调用需确认允许的数据和模型。

## 风险与评审点

- 共享 SQLite 写锁：模型调用移出事务，短批次写入、busy timeout，有界重试。
- 跨权限派生泄露：首期 owner-only + 全来源实时校验；不得把共享知识库权限等同原文权限。
- 幻觉/错误合并：显式草稿与引用，歧义不强行合并；引用存在不证明陈述正确。
- 删除回流：来源抑制同步索引失效，所有读取含历史/邻居复核。
- 费用与恢复：启动前预算，停止后保留检查点，重启不自动调用模型。
- 发布原子性：以页为单位，不声称多页全库原子发布；跨页链接先显示未发布目标不可用，后续发布后恢复可访问。
