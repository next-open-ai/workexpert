## 当前自动验证

```bash
pnpm --filter @workexpert/contracts build
pnpm --filter @workexpert/agent-core typecheck
pnpm --filter @workexpert/api typecheck
pnpm --filter @workexpert/agent-core test
```

阶段验收还必须覆盖一次真实 Embedding 服务和 LanceDB 的端到端混合检索，不以纯单元测试代替。

- ONT-TEST-24：后台抽取任务返回任务 ID，页面刷新后可恢复查询状态并在完成后进入候选整理。
- ONT-TEST-25：候选增删改、暂缓和合并不会直接修改正式图谱，暂存后才形成待发布草稿。
- ONT-TEST-26：发布前返回变更摘要与分级校验；版本发布记录说明，回滚以新版本保存且不覆盖历史。
- ONT-TEST-27：规则扫描识别重复实体、命名问题、孤立节点、无效端点、自循环和重复关系，并准确区分阻断与建议。
- ONT-TEST-28：合并治理命令迁移关系、合并别名和属性并写入操作记录；撤销恢复操作前草稿。AI 输出只能通过治理命令契约。
# ONT-27 回归

- 限定候选入草稿不处理其他已接受候选；重复入草稿幂等。
- 关系缺少端点时拒绝入草稿，保留审核结果供修正。
- 运行时打开审核不停止分析；关闭返回分析；任务完成不覆盖审核结果。
- 无候选 ID 的旧任务不得自动混入历史候选；状态数字明确区分实体和关系。
- 四步导航：候选管理与实时分析归第二步，质量检查与发布归第三步，发布后进入第四步召回验证；查看历史步骤不推进实际进度。
- 分析未结束仍可审核当前结果并发布当前草稿；正式版本仅包含已入草稿结果，界面提示后台后续候选不包含在当前版本。
- 草稿存在阻断问题时禁用发布，并能返回质量检查；无问题可跳过详细检查进入发布确认。
- 发布预览 draftOnly=true 时排除未入草稿的 accepted 候选；已确认模型规则的阻断问题在检查与预览阶段可见，发布执行相同规则。

## ONT-28 视觉验收

- 三个主入口等宽，标题、说明和选中态清晰；图谱数量不挤占其他入口。
- 规则入口与主导航分层，分析状态元信息颜色统一；警告/失败保留语义色。
- 主入口支持键盘焦点，窄屏纵向排列，减少动态效果时取消位移动画。
- 保持现有四步流程、分析任务和图谱编辑行为；前端类型检查及构建通过。

## ONT-29 控制回归

- 跳过等待中的第二批，保留第一批候选并继续第三批；跳过不触发重试或熔断。
- 停止时取消所有在途模型请求，未启动批次不调用模型；已完成结果保留，全部未完成切片可继续。
- 模型忽略取消且迟到返回时不得导入结果；保存中的成功批次仍须完成保存。
- 同一过期批次不能误取消通道下一批；无权限不能控制其他知识库任务。
- 停止后进入检查；有候选无草稿时先审核，无任何结果时禁用发布并提供返回调整入口。

## ONT-30 批量审核验收

- 全部接受/全部拒绝仅作用当前审核范围，按钮展示实际待更改数量；之前的选择可统一改选，staged/committed 项不受影响。
- 请求中禁用重复或冲突操作；失败在弹窗显示原因，已完成批次状态保留，重试只提交尚需更改的项。
- 切换片段时更新数量，全部接受后可加入草稿，全部拒绝后不会把已拒绝项加入草稿；构建和类型检查通过。
