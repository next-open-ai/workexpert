# 需求规格

> 状态：待评审｜规格版本：0.1｜更新日期：2026-09-23

| ID | 需求 | 验收摘要 |
| --- | --- | --- |
| ONT-01 | 系统应按知识库保存节点、关系、属性、别名、来源和发布状态。 | 重启后可读取；不同知识库隔离。 |
| ONT-02 | 查询应识别标准名称及别名，并返回匹配实体、相邻关系、扩展词和结构化条件。 | “退钱没收到”可归一到“退款未到账”。 |
| ONT-03 | 原始问题的向量召回必须始终保留，不因图谱缺失或误识别而被阻断。 | 无图谱或无匹配时退化为普通向量检索。 |
| ONT-04 | 图谱结果应增强而非替代向量检索，可扩展查询、提供目标文档提示和排序信号。 | 结果中可观察检索策略与查询计划。 |
| ONT-05 | 权限、有效期、版本和适用范围属于确定性过滤职责，不得交给大模型自由决定。 | 后续过滤层必须位于模型上下文组装之前。 |
| ONT-06 | 图谱结论应能追溯到原始文档、切片、项目、流程或经验。 | 节点/关系支持 source 与 documentId 等证据引用。 |
| ONT-07 | 第一阶段应支持本体替换、读取、查询和混合检索 API。 | 契约校验失败返回 400；成功结果结构稳定。 |
| ONT-08 | 每个知识库应具备草稿、发布版本、候选事实、人工审核和正式提交闭环。 | 未审核候选不进入正式图谱；接受后提交可被查询规划命中。 |
| ONT-09 | 候选节点和关系必须至少携带一条文档证据。 | 契约拒绝无 evidence 的候选；提交后保留 documentId/chunkId。 |
| ONT-10 | 用户可选择知识库文档并用已配置的应用模型自动识别实体、关系和证据。 | 模型输出只形成待审核候选，不直接修改正式图谱；每条候选可追溯到原始切片。 |
| ONT-11 | 默认界面应采用“选择文档—AI 分析—人工审核—批准入库”流程，JSON 编辑仅作为高级能力。 | 业务用户无需编写 JSON；可逐条或批量接受/拒绝候选。 |
| ONT-12 | 多切片文档的自动识别应分批生成结构化结果，并在单批输出不完整时自动缩小范围重试。 | 大文档不再因一次模型输出过长而整体失败；源切片内容和证据边界保持不变。 |
| ONT-13 | 单条模型候选的证据无法在授权切片中核验时，应丢弃该候选而不是中止整篇文档分析。 | 可信候选继续进入审核区；引用无效节点的关系一并丢弃；未授权 chunkId 仍拒绝整次请求。 |
| ONT-14 | 知识库详情应提供可视化本体检索验证，展示查询规划、增强策略和最终知识片段。 | 用户无需调用 API 即可判断实体、别名、一跳关系和本体增强召回是否生效；验证操作只读。 |
| ONT-15 | 知识库详情应将已审核写入的正式本体以关系图展示。 | 用户可查看实体、关系、类型图例和属性详情，可搜索定位、切换布局及缩放；大图限制首屏节点数且不影响完整存储。 |
| ONT-16 | 多切片本体抽取应在 Provider 可承受范围内减少模型往返并采用有界并发。 | 默认按最多 2 个切片、约 4500 字符动态装批；Qwen 与本地模型最多并发 2 批，其他云模型最多并发 4 批；标准输出预算 1400 token，结果顺序稳定，失败批次可独立继续。 |
| ONT-17 | 正式本体关系图应支持沉浸式全屏查看。 | 用户可从图谱标题区进入全屏，保留搜索、布局、缩放和详情交互，并可通过按钮或 Esc 退出；画布随窗口尺寸刷新。 |
| ONT-18 | 本体查询应提供受控图查询约束、最多两跳的可解释路径和证据驱动的混合召回。 | 查询可限制实体类型、关系、属性与方向；结果展示路径和证据引用；原始向量召回始终保留，图谱绑定切片作为独立召回路径参与融合。 |

## 非目标

- 不建设完整企业级图数据库；
- 不实现三跳以上复杂推理；
- 不允许模型抽取结果未经审核自动成为正式制度；
- 不在第一阶段替换 LanceDB、云知识库或现有经验存储；
- 不允许模型抽取结果绕过人工审核直接写入正式图谱。

| ONT-19 | 本体构建采用五步、可恢复、可回退的治理工作流。 | 支持资料选择、后台识别、候选整理、图谱审核和版本发布；候选可人工新增、编辑、暂缓或删除；发布前执行阻断/建议校验；回滚生成新版本。 |
| ONT-20 | 图谱审核必须提供可操作的问题治理中心，并允许 AI 生成受控修复建议。 | 问题按重复、命名、孤立、端点缺失、自循环和重复关系分类；支持局部图、合并/删除/重命名等受控命令、影响说明、忽略、操作历史与撤销；AI 只能返回白名单命令并由用户确认后应用到草稿。 |
| ONT-21 | 本体创建工作台应具备不可越级、可恢复和防误操作的专业交互。 | 分析状态与结果持久化；服务重启后的运行中任务明确标记中断；步骤按前置条件解锁；候选支持完整业务字段编辑；批量审核二次确认并提示低置信度风险。 |
| ONT-22 | 已发布本体应受控接入数字员工默认知识检索，并具备发布权限与故障降级。 | 仅管理员可发布或回滚；发布人取自登录身份；知识库默认启用本体增强且可单独关闭；本体异常时自动退回原始检索。 |
| ONT-23 | 规则未命中时，可由独立应用模型在受限候选内执行语义实体链接。 | 模型只接收有界候选且只能返回已有 ID；置信度阈值为 0.72；8 秒超时、无配置、非法输出或网络失败均退化为无语义命中，并保留原始向量检索。 |
| ONT-24 | 非 JSON 办公文档应复用统一的本体抽取与证据治理链路。 | PDF、DOCX 和已安装解析组件的 PPTX/PPSX 先转正文与切片，再抽取候选；证据仍绑定原文切片，扫描内容需 OCR 解析能力。 |
| ONT-25 | 本体抽取应优先返回高价值业务候选，并限制慢请求和重复计算造成的长尾等待。 | 按 Provider 能力采用有界并发与超时；超时批次缩小范围续跑一次；结构错误最多缩小一次；相同模型、指令和切片可复用进程内缓存；首批结果立即保存并允许先审核；即使全部失败也保留完成/失败切片检查点，并只续跑未完成切片。 |
| ONT-26 | 本体抽取失败应可诊断、可止损并保持断点续跑。 | Qwen 默认以单切片、单并发、`json_object`、120 秒兼容模式执行；每批持久化错误分类、耗时和安全摘要；输出截断、非法结构和证据问题只缩小或跳过当前切片并继续，连续两个服务级故障才暂停后续提交；未处理切片保留为可续跑检查点；界面显示实际原因而非统一归因为超时。 |
# ONT-27 增量审核与草稿隔离

分析与审核并行；每批候选落盘后才公布候选 ID 和完成切片。审核弹窗固定本次候选快照，不混入历史数据，不自动发布；入草稿仅处理明确选择的已接受候选，校验关系端点。关闭回到分析，不取消任务。完成任务不得覆盖最新审核状态。图谱入口展示已发布及草稿实体/关系数量。续跑沿用未完成切片范围，保留已完成结果。

构建导航统一为“选择资料 → 分析与审核 → 检查与发布 → 召回验证”。人工候选管理属于分析与审核；质量检查及发布确认属于同一步内的操作。查看历史步骤不推进进度；分析仍运行时保持第二步进行中。发布成功后进入独立召回验证页，可返回当前发布记录。质量检查无问题时可跳过详细检查；有阻断时须提供返回处理入口并禁用发布。

发布预览新增可选 draftOnly（旧调用默认 false，保持兼容），工作台使用 true，仅统计已入草稿的节点和关系；预览与发布使用一致的图结构及已确认模型规则校验。接受但未入草稿的候选不得进入发布摘要或被误标记为已发布。

## ONT-28 工作台视觉层级

本体图谱、AI 辅助构建、AI 优化为等宽同级主入口，显示功能说明、清晰选中态、悬停及键盘焦点反馈。图谱入口只显示已发布/草稿实体数量，关系明细保留在图谱范围工具栏；业务知识规则为辅助入口。四步流程与内容分层，进度不因查看而推进。分析元信息统一中性色，只突出候选与需要继续处理的状态。窄屏入口改为纵向布局，支持减少动态效果偏好；不改变分析、审核、发布行为。

## ONT-29 用户跳过与停止分析

运行中的处理卡片支持按明确批次号中止当前请求并继续下一批；单切片显示“跳过此切片”，多切片请求明确提示跳过整批及切片数量。跳过不重试当前请求、不触发服务熔断、不标记为已完成；保存为可继续处理的切片。过期的批次操作返回 409，不得中止通道中已开始的下一批。

“停止分析，检查已有结果”中止所有当前请求并停止后续调度，等待在途保存完成后返回包含已完成候选和未完成切片的结果，进入检查与发布。未审核候选仍需先审核、加入草稿；没有草稿时展示明确空态并禁用发布。已成功候选和检查点保留，后续继续只处理未完成切片；模型取消后迟到的输出不得写入候选。新控制接口沿用知识库所有权鉴权，运行时控制器不持久化，旧任务记录兼容读取。

## ONT-30 弹窗批量审核

审核弹窗固定底栏提供“全部接受”“全部拒绝”及实际影响数量，仅操作当前选定片段/任务快照范围内尚未入草稿的候选，可统一改选此前的接受/拒绝决定。已入草稿和已发布候选不受影响。批量操作后即时刷新数量、候选状态和可入草稿按钮；不自动发布。请求中禁用重复提交及相冲突的编辑/审核操作，失败显示错误并保留已保存选择。超过单次审核接口 1000 条上限时分批提交，保持任务快照范围不变。
