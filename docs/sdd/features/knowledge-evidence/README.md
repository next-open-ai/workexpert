## 架构与契约

公共 Zod 契约在 `packages/contracts/src/knowledge-evidence.ts`。Node 身份计算在 `packages/agent-core/src/knowledge-evidence.ts`，不读取用户文件、不调用模型、不写数据库。

`KnowledgeEvidence` 是 schemaVersion=1 的区分联合：versioned 必须有 documentVersionId、processingRevisionId、contentHash；legacy-unverified 禁止冒充已验证引用。两者均需 provider、knowledgeBaseId、documentId、chunkId。授权仍由调用方执行，身份与哈希不构成授权证明。

`sourceLocation` 当前仅表示 normalized-text 的 UTF-16 半开区间，不声称是 PDF 页码或原文件字节偏移。parentChunkId 可选，后续仓储必须验证父子处于同批次。Chunk 哈希基于精确 UTF-8 文本，不自动 trim 或换行转换。

文档身份由宿主分配，不按文件名推测。版本 ID 为 provider、KB、documentId 和原始字节 SHA-256 的确定性摘要；处理身份加入 parser、chunker 版本和规范化配置；Chunk 身份加入处理身份、序号和内容摘要。配置只允许 JSON 对象，键排序，禁止密钥参与配置。辅助函数验证非法输入并抛 ZodError/TypeError。

## KE-T04b：结构化分块、定位与父块上下文（KE-01/02/05/06）

范围：新本地入库采用确定性 Markdown/纯文本结构启发式分块，优先标题、段落、列表、管道表格、围栏代码边界。子块上限 1,200 UTF-16 单位；超长结构按换行、句子/空白边界降级，再做 Unicode 安全硬切。不承诺完整 Markdown AST、HTML 表格、OCR 或 PDF 页码恢复。规范化为 CRLF/CR→LF 后 trim，定位为该解析文本的 UTF-16 半开区间；正文必须等于区间切片，不拼接标题或表头冒充原文。

同一标题区段内多个子块聚合为最大 3,600 字符父块；单子块不冗余建立父块。子块参与 Embedding/FTS/列表/计数，父块只作为同批次 parentChunks 保存在证据 JSON，不进入 membership/向量/FTS，不重复参与排名。父子含同作用域/版本、内容摘要与定位，子块 evidence.parentChunkId 指向父块；headingPath 仅元数据，不篡改片段内容。新 chunker recipe 为 structured-utf16-v1，身份随版本变化；旧批次不自动重处理、不伪造定位或父块。

证据 schema v4 只提升兼容版本标识，不改旧表、不重写旧 payload；防止旧严格解析器误读带 parentChunks 的新批次。契约新增可选 parentChunks、versioned headingPath、KnowledgeParentContext。存储拒绝错作用域/错摘要/循环/重复父子身份、位置越界及子内容不等于父区间切片；旧批次无定位仍兼容。父块按独立上下文集合维护，不支持父块再嵌套。

检索保留 hit.content 和 child evidence；另返 context（父正文、父 evidence、matchedChunkIds），最多每次 7,200 字符，同父只附一次，不改变召回分数/结果数。工具最终跨库 TopK 后重新恢复并执行全局预算，模型须区分命中证据与补充上下文，不将未命中邻段冒充关键词命中。上下文仅来自当前有效批次；任一同父子块被屏蔽时暂不恢复整个父块，避免删除内容通过兄弟块泄漏。本体混合后的最终输出重新核验/恢复，不能保留早先异步查询的陈旧上下文。

交互：沿用导入、搜索和片段详情；搜索结果正文仍是命中片段，可用折叠“查看上下文”查看补充段落，不增加配置或管理入口。旧数据无上下文时不显示折叠控件。不展示内部父子 ID，也不称规范化文本位置为原文件页码。

KE-C01：结构边界/长段/长列表表格/围栏/标题路径、重复文本、CRLF、emoji、范围切片与确定性；KE-C02：父子合同/内容校验、只索引子块、v3→v4 保留历史、删除兄弟块抑制上下文；KE-C03：真实 Lance + mock Embedding 的入库/混合检索/本体/工具上下文、去重/预算、旧批次兼容、重处理/删除后不泄漏。执行 contracts/storage/agent-core/API 回归、类型/构建、Electron Node 和并发回归；人工 UI、安装包及大库相关性基准另验收。

回滚必须保留 v4 兼容读取，可停用新分块与上下文恢复，但不能直接降级到 v3 严格解析器；不删原文或证据。不实施替换/重处理 UI、Reranker、Wiki、WeKnora Provider 或 ANN。

## KE-T04a：全文与混合召回（KE-06）

范围：本地知识默认关键词/BM25 + cosine 向量召回，RRF（k=60，等权，两路各取最多 100 个候选）融合，不增加入口、开关或服务。SQLite FTS5 使用预处理 token：NFKC、小写、英文/数字词、汉字单字及相邻双字；多字中文查询优先双字，查询最多 64 个去重 token，按 OR 召回。不是语义中文分词、同义词或 Reranker。标点作为普通查询输入，不接受 FTS 查询语法。

evidence schema v3：新增派生 search_chunks 与 external-content FTS5 表/同步触发器。只索引当前有效且未屏蔽分块；CAS 发布与全文替换同事务，失败保持旧头，删除同事务移除全文行，历史批次不参加 BM25 词频统计。v1/v2 升级事务自动回填有效证据；旧批次缺标题时使用内容摘要，不伪造原文标题。新批次可选 documentTitle/source；旧批次重试保留原元数据。

旧 LanceDB/JSON 无版本分块在进程首次检索时分批补索引，后续正常入库同步维护，不升级为 versioned。失败不标记补齐，重试幂等；筛除屏蔽、已托管及 ch- 孤立块。此补齐不提供外部直接修改底层文件后的实时同步，重启可重扫；不改变历史文件。查询时仍做发布/删除校验，证据库损坏不得降级绕过。

公共契约：KnowledgeSearchChunk / KnowledgeKeywordHit，以及检索明细 KnowledgeRetrieval（channels、ranking、degraded）；正文与标题的 FTS token 列权重为 1/2。BM25 原始值越小越好，不直接与 cosine 分数相加。RRF 分数按 61/2 缩放到 [0,1]，不代表概率。无 Embedding 配置时关键词独立可用；Embedding 异常且有关键词命中时返回明确标记 degraded 的关键词结果，无命中保留原错误。空白查询直接返回空列表。现有本体扩展继续叠加，strategy 对本地返回 hybrid，非本地 provider 不变。

任务 KE-T04a 影响 contracts/storage/agent-core/API 返回与 renderer 路由类型，不改变项目、治理、资产、权限和模型配置。KE-K01 验证 token/特殊字符/中文/编号及真实 BM25 排序；KE-K02 验证迁移、幂等、发布失败回滚、删除和作用域隔离；KE-K03 验证真实 Lance + mock Embedding 的词/向量互补、去重、降级、历史补齐、版本和删除闭环。执行相关包测试、类型检查、构建、Electron Node 模式、并发回归。安装包/大库性能另验收。

全文发布失败返回 FULLTEXT_INDEX_FAILED，旧头/索引事务回滚。旧 retrievalRoutes 中 raw-vector/ontology-vector 键为兼容保留，表示原始/扩展查询来源；实际关键词/向量参与情况以 retrieval.channels 为准。

回滚保留 schema v3 及 v3 兼容可见性读取，可停用混合查询但不可直接运行只认识 v2 的代码或删除数据库。全文为可重建派生数据；本步不提供用户手动重建/清理界面。FTS5 行为依据 [SQLite 官方文档](https://www.sqlite.org/fts5.html)。

## KE-T02a：SQLite 批次仓储（KE-04/05）

T02 分为 a：元数据/证据快照仓储，b：原文件归档与安装态验收。本次只实现 a，不接通生产入库。`storage` 依赖 `contracts`，不依赖模型层；宿主提供专用数据库路径并执行授权，不接受用户输入直接作为路径。使用运行时内建 `node:sqlite`，延迟加载，缺失时显式失败，不降级覆盖旧库。

`KnowledgeEvidenceBatch` 包含 scope、documentVersionId、processingRevisionId、sourceHash、chunks（versioned evidence + content）。仓储保存不可变完整快照；同批次重复写相同内容幂等，不同内容报 CONFLICT。校验 chunk 作用域、版本、内容哈希、父子关系及环；空批次拒绝。原文件、解析配置与定位原文的核验留给 T02b/T03。

快照写入不发布。`activate(scope, revision, expectedGeneration)` 由索引成功后的调用方执行，事务内比较文档 generation 并递增，防止迟到任务覆盖新批次；失败或未发布快照不影响旧有效批次。generation 同时作为回滚/重新发布的乐观锁，历史快照仍可读。此方法本身不证明外部索引就绪。返回错误码 NOT_FOUND / CONFLICT / INVALID_BATCH / UNSUPPORTED_SCHEMA。

独立数据库 application_id + user_version=1；仅初始化空库，拒绝未知或更高版本数据库。DDL 在事务内执行；外键、busy_timeout、WAL 开启。不得打开现有 ontology.sqlite。回滚为停用新模块并保留新数据库；不做破坏性降级。

验收测试 KE-S01：重开持久化/幂等/历史；KE-S02：双连接 generation 冲突与失败保持旧批次；KE-S03：内容/父子/作用域拒绝且事务无半写；KE-S04：未知库/未来版本拒绝且原数据保留。使用临时库验证，生产库不迁移；Electron Node 模式另跑相同测试，安装包验收仍属 T02b。

## KE-T02b1：不可变原文快照与资产桥接（KE-04）

目标架构：文件对象保存原始字节，SQLite 保存权威版本/证据，LanceDB 是可重建检索副本。新增共享 `ImmutableFileStore`，不改变旧资产目录、更新或删除行为；旧资产导入时复制独立快照，不用硬链接，资产覆盖或删除不破坏快照。未来再将资产接入相同文件对象，不做跨用户去重。

本步范围：本地 `/knowledge/ingest` 先归档源输入，再走既有解析和向量入库；API 分配 documentId 并传给 agent-core，成功响应增量返回 sourceSnapshot。文件输入保存精确字节，文本输入保存未经 trim 的 UTF-8；兼容既有 content 优先规则。新增可选 assetId，禁止与 content/fileBase64 混用，只允许本地 provider；仅允许导入当前用户、当前组织的自有资产，暂不开放共享资产转存。原文读取端点按认证用户+组织隔离，不使用客户端路径。

源文件对象按 owner 分区和 SHA-256 定位；公开引用不包含绝对路径。写入临时文件并 fsync 后以不覆盖目标的方式发布；读取拒绝符号链接并核验 hash/size。宿主根目录必须可信、不可由其他本机用户修改。元数据写在独立 sources.sqlite（application_id、user_version=1），事务初始化只接受空库或本库；不会迁移旧资产或证据库。先文件后元数据，崩溃最多留下未引用文件，不能产生成功但缺文件的引用；无自动 GC/删除接口。

快照状态只表示 archived，不表示解析、Embedding 或证据批次发布成功。解析失败保留快照用于后续恢复，不回滚删除原文；原有删除文档动作仅删除检索内容，不等于彻底删除归档，须在后续管理界面与清理流程中明确。不回填已有文档、不改变当前向量表结构或接通证据批次、不引入 FTS/ANN。

KE-F01：文件字节保真、幂等、修改源文件不影响快照；KE-F02：路径穿越/符号链接/损坏拒绝；KE-F03：元数据持久化、版本冲突、owner 隔离、未知数据库保护；KE-F04：API 文件/文本/资产导入、授权拒绝、失败留存、下载隔离。运行 storage/API/agent-core 回归、构建、Electron Node 模式验证。安装态与跨平台另验收。回滚代码后保留新文件目录及 sources.sqlite，不删旧数据。

## KE-T03a：证据批次接线与统一可见性（KE-03/04/05）

API 将可信 sourceSnapshot 传入 agent-core，后者在 API 进程中调用 storage 仓储。新本地入库顺序为：归档 → 解析/分块 → SQLite 不可变批次 → Embedding/LanceDB 写入 → CAS 发布。处理身份记录解析器标签、分块器版本及解析结果摘要；本步仍用原分块器，不虚构页码或来源定位。新分块 ID 为 ch- 前缀；不修改 LanceDB 表结构，批次归属由 SQLite membership 表关联。

证据数据库位于各知识库 dataDir 下 knowledge-evidence.sqlite，schema v2：在事务中增量添加 membership 与 suppressed_chunks，回填已有 v1 批次身份，不改原 payload。保存逐块正文仍以批次快照为准。新版本化写入不再静默降级 JSON：LanceDB 写入或校验失败必须报错，旧批次保持有效。旧无版本文档和 JSON fallback 继续可读，引用标记 legacy-unverified。

查询、文档列表、分块列表及本体证据召回统一排除待发布/过期/删除的分块。向量查询在 TopK 前做有效 ID 过滤，返回后重新校验避免查询期间切换泄漏；失去 SQLite 记录的 ch- 分块 fail closed，不当成 legacy。旧 JSON 与 LanceDB 结果合并去重，显式使用 cosine 距离和统一分数转换。SQLite 异常不得被吞掉后返回未经筛选结果。

删除采用持久化逻辑屏蔽后再尝试清理检索副本，历史原文/证据保留；文档删除提升 generation、清空有效头，阻止进行中的旧任务再次发布；单块删除记录屏蔽 ID。没有新增历史版本、批次或数据库选择 UI，也不按同名文件自动覆盖。默认新导入仍产生新文档，用户的替换/重处理入口后续单独建设。

交互：保留现有导入按钮与处理中/成功/失败状态，成功文案使用“可检索”而非“索引已写入”；失败保留已填写内容，不把 archived 显示成入库成功。旧知识无需重新导入。暂不做父子块、FTS、ANN 或 Wiki。

KE-V01：v1→v2 迁移保留历史、成员冲突回滚；KE-V02：未发布不可见、CAS 失败保持旧头、删除阻止迟到发布；KE-V03：真实 LanceDB + mock Embedding 下入库/检索/列表/删除/旧 JSON 兼容；KE-V04：向量写入失败不发布；KE-V05：API 快照贯通与简洁反馈。保留 v2 数据时不能直接降级到无版本过滤代码；回滚须停用新写入并保留兼容读取/屏蔽逻辑，不删除证据库。
