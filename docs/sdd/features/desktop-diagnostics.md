# 桌面打包与运行诊断日志

## 需求、任务与契约

- DL-R01 / DL-T01：打包 stage 输出平台/架构、阶段耗时、每个生产依赖大小、原生组件和资源目录大小；只报告构建资源，不打印环境变量或凭证。
- DL-R02 / DL-T02：主进程独占写入 `app.getPath('logs')/runtime.log`，JSONL v1 格式含时间、级别、来源、固定事件名及允许的诊断元数据。每文件最多 5 MB，保留 3 个历史文件。创建目录 0700、文件 0600；写日志失败不影响业务并只向 stderr 提示一次。
- DL-R03 / DL-T03：安装包 API stdout/stderr 改为管道接收；仅持久化结构化白名单字段，不保存 body、prompt、文档正文、密钥、原始模型输出或未知文本。保留请求 ID、HTTP 方法/状态、耗时、错误码；未知输出仅记录字节数，已知模块加载错误保留故障类别。开发态保留原有终端输出。
- DL-R04 / DL-T04：原生帮助菜单提供查看当前日志、打开日志目录；只能打开固定日志路径，不接受 renderer 传入路径。无日志时明确提示；失败使用原生提示，不阻塞业务。无新增网络接口、无外部上传；设置 IPC 见下。
- DL-R05 / DL-T05：知识入库失败记录固定事件及安全错误码（包括 cause.code），方便关联请求，不保存异常正文。
- DL-R06 / DL-T06：设置 → 通用增加本机“运行日志”开关，默认开启（兼容当前行为），立即生效、重启保留；关闭后主进程及接收的 API/renderer 事件均不写文件，保留历史日志。Actions 构建日志与开发终端输出不受影响。浏览器模式显示桌面专属说明，不伪装可用。

### 开关 IPC 契约与状态

`getRuntimeLogSettings(): Promise<RuntimeLogSettings>`、`setRuntimeLogEnabled(enabled: boolean): Promise<RuntimeLogSettings>`；响应 schema 在 contracts，`{enabled:boolean}`。仅主窗口主 frame 可读写；原生帮助菜单和设置查看按钮只打开固定日志路径。主进程在 userData/diagnostics.json 保存私有 v1 设置，原子替换后才改变内存状态，保存失败保持原状态。配置损坏/未来版本时保守关闭，不自动覆盖；用户显式保存可恢复。无域 KV 新写者、无网络 API、无数据迁移。
UI：读取时禁用开关，保存中防重复提交，失败保留旧值并可重试；保存成功显示已开启/已关闭；关闭后仍可打开已有日志，无历史文件时明确提示“暂无运行日志”，不为了打开而写入新日志。

## 范围与兼容

调整 desktop 日志、renderer 通用设置、contracts 设置响应和 API 入库错误观测，不更改入库成功/失败语义、权限、编排、模型调用和业务数据 schema。结构化日志为本机诊断，不是审计台账；不自动清理任何知识数据。回滚删除接线和新模块即可，历史日志无需迁移。旧日志轮转时最老日志被自动删除，可分享前需用户自行检查；本机版本/请求 ID 等元数据仍可能敏感。

## 测试规格与追踪

- DL-T01：依赖 staging 回归和新增日志回调断言；文件统计不跟随符号链接，避免循环。
- DL-T02：临时目录验证 JSONL、权限、大小/轮转边界、超长输入裁剪、写入失败降级。
