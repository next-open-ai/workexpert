# 平台架构基线需求

> 状态：待评审  
> 规格版本：1.0.0  
> 更新日期：2026-10-27  
> 关联：[架构规格](architecture.md) · [追踪矩阵](traceability.md)

## 功能边界需求

| 编号 | 需求 |
| --- | --- |
| PAB-REQ-001 | 系统必须支持 Electron Desktop、Web/API 与外部通道三种入口，共享同一服务端业务与编排事实源。 |
| PAB-REQ-002 | Renderer 必须是浏览器安全边界，不得直接导入 Electron、Node 内建模块或读取秘密配置。 |
| PAB-REQ-003 | 模型 SDK、模型 HTTP 与专业能力模型调用只能由 `@workexpert/agent-core` 执行。 |
| PAB-REQ-004 | 会话、运行、审批、项目计划和任务状态必须由 `@workexpert/orchestrator` 维护，并由 API 托管。 |
| PAB-REQ-005 | 公共跨包数据结构必须以 `@workexpert/contracts` 的版本化 Zod schema 为单一事实源。 |
| PAB-REQ-006 | 通道协议必须与 Telegram、飞书、Relay 等传输适配器解耦，Gateway 不得成为第二套编排器。 |
| PAB-REQ-007 | 域 KV 必须由 API 进程单写；Desktop Main 仅托管平台安全能力、密钥和桌面生命周期。 |
| PAB-REQ-008 | Provider、搜索和通道凭据不得进入 renderer、domain KV、模型上下文或普通日志。 |
| PAB-REQ-009 | pi、AgentScope、dsh 必须通过统一执行后端与 `AgentEvent` 语义接入；后端差异不得泄漏为平行业务流程。 |
| PAB-REQ-010 | 工具写文件、运行脚本、网络访问和外部副作用必须经策略或审批控制；不可将工作目录隔离宣传为安全沙箱。 |
| PAB-REQ-011 | 原文、权威证据/治理状态与可重建检索副本必须保持身份与生命周期分离。 |
| PAB-REQ-012 | 运行形态、外部依赖和未完成能力必须显式降级或失败，不得静默扩大权限或伪造成功状态。 |

## 质量属性

| 编号 | 属性 | 要求 |
| --- | --- | --- |
| PAB-NFR-001 | 本地优先 | 核心桌面/API/编排不依赖云端控制平面；云模型和外部通道是显式依赖。 |
| PAB-NFR-002 | 安全 | 身份、owner、路径、权限与密钥由可信进程解析；客户端字段不能覆盖服务端授权结论。 |
| PAB-NFR-003 | 可恢复 | 运行终态、审批停车、取消、重试和 sidecar 失败具有确定语义。 |
| PAB-NFR-004 | 可观测 | 运行、工具、模型用量、并发和 sidecar 状态可通过事件或状态接口观测。 |
| PAB-NFR-005 | 可测试 | 外部系统可替换为 fake/stub；架构边界有静态检查、单元测试或回归脚本。 |
| PAB-NFR-006 | 可演进 | 长期边界变化使用 ADR；功能行为变化进入独立 SDD，不把阶段计划混入平台基线。 |

## 非目标

- 不重新定义各页面交互、业务 API 全量字段或数据库逐表结构。
- 不把架构逆向结果等同于真实 Provider、真机 IM、安装包或生产环境验收。
- 不为尚未实现的方案稿补写“已实现”状态。
